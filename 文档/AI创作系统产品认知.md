# AI 创作系统产品认知与真实现状

> 更新日期：2026-08-05
> 这是一份产品认知文档，不是开发手册，也不是详细 PRD。它描述当前产品是什么、谁在用、已经有什么能力，以及需求和数据应该从哪里了解。

## 0. 先看结论

### 一句话定位

面向信息流广告素材设计师的素材生产工具，帮助设计师对已有素材进行生成、替换、混剪、裂变、批量加工和入库。

### 产品由什么组成

- **通用生成**：主要入口，直接生成图片、视频和文案。
- **工作流**：一组已经封装好的素材加工工具，解决拆分、合成、混剪、替换、裂变、去重等重复动作。
- **我的任务 / 全部结果**：查看任务进度、产出、审核状态和历史结果。
- **人工审核**：处理需要人判断的中间结果或产出结果。
- **原料库**：沉淀脚本、演员、花字、贴纸、音效、BGM、背景等可复用生产资源。
- **素材系统连接**：把产出入库，并记录创作者、任务、工作流和来源关系。
- **H5**：海外场景下的一类特殊素材生产能力。

### 这不是一个什么产品

- 不是创意灵感平台。
- 不是让普通用户学习搭建工作流的平台。
- 不是单纯的模型试玩工具。
- 重点是把素材设计师的常用加工动作工具化、批量化，提升产能，减少重复人工处理。

## 1. 业务链路与用户角色

### 1.1 业务链路

产品提出投放需求 → 优化师根据投放效果提出素材优化方向 → 素材设计师制作和批量加工素材 → 进入投放验证 → 结果再反馈给产品和优化师。

AI 创作系统处在“素材制作”这一段，为素材设计师提供生成、加工、批量处理和入库能力。

### 1.2 角色分工

| 角色 | 作用 |
|---|---|
| 产品 | 提出业务和投放需求，明确要解决的问题 |
| 优化师 | 根据投放效果提出素材优化方向，判断产物是否满足投放需要 |
| 素材设计师 | 直接使用系统完成素材制作、加工和批量出片 |
| 工作流维护人员 | 创建、维护和验证工作流，把重复加工动作封装成工具 |
| AI 创作系统 | 提供生成、加工、批量处理、任务追踪和入库工具 |
| 原料库 | 沉淀可复用的脚本、演员和视听元素，支持后续生产 |

**直接用户是素材设计师。** 优化师和产品是需求来源与结果判断者；工作流维护人员负责把常见做法固化成可用工具。

## 2. 产品边界和判断标准

### 2.1 产品边界

系统主要处理已经存在的投放素材，而不是从零发散创意。典型动作包括替换、混剪、裂变、抽帧、调速、去重、字幕处理和批量生成变体。

工作流的价值不是让用户研究节点，而是让设计师少做重复操作、一次处理更多素材，并减少人工处理成本。工作流搭建属于工作流维护人员的工作，不是普通素材设计师的主要任务。

### 2.2 判断功能是否有价值

优先看四件事：

1. 是否解决了真实投放素材的加工问题。
2. 是否减少了素材设计师的重复操作。
3. 是否能批量、稳定地得到可继续使用的结果。
4. 是否能让结果回到任务、审核、素材系统和后续投放链路。

## 4. 主要使用场景

素材设计师常见的工作不是“想一个新创意”，而是把已有素材快速加工出更多可投放版本：

1. **已有投放素材二次加工**：保留有效内容，只替换产品演示、演员、字幕、花字或其他元素。
2. **批量生成变体**：一个素材生成多个版本，改变开头、节奏、画面、颜色、贴纸或其他可控因素。
3. **视频拆分、合成、混剪**：拆分原视频、重新组合片段，并在需要时还原原片段位置。
4. **产品演示替换**：把原素材中的产品演示替换成新的录屏或产品内容；部分场景存在“先生成、后算法替换”的两阶段处理。
5. **视频裂变和去重**：抽帧、调速、调色、改变画面或声音、随机贴纸等方式生成差异化版本。
6. **字幕和重点信息处理**：去除字幕、添加字幕、突出重点信息或生成高亮片段。
7. **从通用生成继续加工**：通用生成结果直接进入工作流，不必下载再重新上传。
8. **从任务结果继续使用**：对结果进行查看、下载、送审或入库。
9. **使用原料库继续生产**：取用脚本、演员和视听元素，继续生成或进入 LibTV 等后续制作环节。
10. **海外 H5 素材生产**：根据海外业务需要，把产品信息、图片、语言、时间和链接等内容组装成 H5/HTML 素材。

## 6. 原料库

原料库不是单独的“素材展示页”，而是为后续素材生产提供可复用资源。它要解决的是：已经验证有效的脚本、演员和元素，不要每次重新找、重新做。

### 6.1 第一阶段：脚本和演员

- 建立脚本库和演员库。
- 支持文件夹、标签、筛选和共享权限。
- 跑量素材中符合条件的内容可以自动沉淀。
- 工作流产出经过业务确认后，可以沉淀为原料。
- 支持下载和继续使用，尤其是下载到 LibTV 做后续制作。
- 记录下载量，帮助判断哪些原料真正被复用。

对应的业务链路是：爆款视频 → 逆向脚本 → 脚本裂变 → 更换演员或元素 → 继续生成新素材。

### 6.2 第二阶段：视听元素

- 花字
- 贴纸
- 音效
- BGM
- 背景
- 接入编辑器、画布和发布链路。
- 建立“原料 → 成品”的关联关系，便于后续查看和衡量效果。

主要证据：XNWT-277（原料库整体需求）、XNWT-712（产出一键入库）。原料库完整上线范围和当前线上页面仍需单独核验。

## 9. 当前真实问题

这是当前工作流体验的核心问题：

- 用户不知道该选哪个工具。
- 用户不知道需要准备什么输入。
- 用户不知道会得到什么输出。
- 工作流限制和适用条件不明显。
- 失败原因和补救方式不清楚。
- 工作流、任务结果、通用生成和原料库之间还不够连贯。
- 当前入口更多是“找工作流”，还不是“按素材问题找工具”。

因此，后续优化的重点不是增加更多按钮，而是让用户能快速判断：**我手上的素材要解决什么问题、应该用哪个工具、要准备什么、结果能不能继续用。**

- `[已确认]`：用户明确说明，或有实时数据直接证明。
- `[当前状态]`：已上线或正在使用的能力；如证据不完整，会在文字中说明“细节待核验”。
- `[需求中]`：Teambition 或需求文档中已有，但没有证据证明已完整上线。
- `[原型参考]`：仓库中存在的页面或交互，只能说明设计参考。
- `[待确认]`：目前没有可靠证据，不能直接作为产品结论。
